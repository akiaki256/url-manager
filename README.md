# URL管理ツール

よく使うURLや、メモを、タイルベースで管理できる情報ダッシュボード（Webアプリ）です。

![スクリーンショット](/img/sample01.png)

## 概要

既存のブラウザのブックマークやスタートページの見た目・使い勝手を自分好みにしたい、という思いから制作しました。

登録したURLをタイルとして一覧表示することで、ファイル構造ではなく画面の位置関係としてURLを管理することが可能です。

リンクタイルとテキストタイルの二種類のタイルが存在し、どちらも画面上の好きな位置に配置できます。

データはブラウザのローカルストレージに保存されるため、再訪時も登録内容が保持されます。

「シンプルでモダンなUI」を目指し、必要な機能は実装しつつ過剰な機能・装飾は避けています。

HTML / CSS / JavaScript の学習を兼ねて、実際に自分が使いたいものを形にすることを目標に開発しました。

## 主な機能

### タイル形式での一覧表示
- 登録したURLをタイルとして並べて表示。ドラッグ&ドロップでタイルの位置を自由に並び替え可能

### リンクタイル
- URL、名前、メモを設定し、リンクへのショートカットを作成するタイル
- ファビコン表示 ... 設定したリンク先からファビコンを取得しタイルに自動表示
- メモ機能 ... 各URLにメモを紐づけて保存
- 表示オプション ... 「タイルに名前を表示」「新しいウィンドウで開く」をチェックで切り替え
- 右クリックメニュー ... タイルを右クリックで詳細（名前・URL・メモ）表示と、編集・削除

### テキストタイル
- メモを直接書き込めるサイズ可変のタイル
- 編集可能なテキストエリア ... メモやToDo管理に利用できます
- 自由なサイズ調整 ... タイル単位でサイズ変更が可能
- 右クリックメニュー ... タイル上部を右クリックで削除メニュー表示

### ローカルストレージ保存
- 登録内容をブラウザに保存し、設定内容を保持

## 使用技術

- **HTML / CSS / JavaScript**（フレームワークを使わない素の実装）
- **Web Storage API（ローカルストレージ）** ... データの永続化
- **CSS ネスト記法** ... スタイルの構造化・保守性向上

その他：Font Awesome（アイコン）、ress（CSSリセット）

## 工夫した点

### リンク集から情報ダッシュボードへ
URLをタイル形式で管理することを目的としたwebアプリとして開発を始めました。しかし、リンク集として常にブラウザ上のタブを一個占有する使い方を考えたときに、リンクの管理だけではもったいないと考えました。そこで「グリッド形式でリンクを管理するページ」から「グリット形式でよく使う情報を管理するページ」へと方向転換しました。

### state オブジェクトに状態を集約
タイルに保存した情報、タイルの枚数、今どのタイルを操作しているか等を state オブジェクトに集約しました。こうすることで分割したJavaScriptファイルのどれからでもリアルタイムな情報を参照することが可能になります。

### 複数マスを有するタイルの実装
1*1サイズのタイルの実装は容易でしたが、複数マスを有するタイルの実装では苦戦し、その結果いくつかの工夫を施しました。ここではその中の２つを紹介します
- **タイルの移動** ... ドラッグ操作でタイルを移動可能にしていますが複数マスを持つタイルを存在させようと思うと「移動先に他のタイルがあったら？」「画面端にドラッグさせたら？」「拡大縮小はどう実装する？」などの多くのハードルが現れます。これらに対処するために、画面端を表す集合と使用済みタイルを管理する集合を用意し、衝突判定を設けることでタイル移動の可否を決定します。
- **使いやすいUIであるか** ... タイルを指定した場所に移動できるかを直感的に理解できるUIを実装しました。ドラッグで移動させることができるなら移動先が青く、移動先に問題があれば赤くタイルが光るようにしております。

### イベント処理とデータ設計の見直し

開発当初は、各タイルの要素一つひとつにイベントリスナーを付け、タイル自体に処理を持たせる書き方をしていました。しかし開発を進める中で、タイル群の親要素にリスナーをまとめて設定し、クリックされたタイルのインデックスを起点に処理を適用する方式（イベント委譲）へと全面的に書き換えました。

「画面から値を受け取る→処理する→結果を画面に返す」という流れを一貫させることで、構造が直感的になり、仕様変更にも強くなりました。特に、ドラッグ&ドロップによるタイルの並び替えは、この設計にしたことで実装が大幅に容易になったと考えています。

### 継続的なリファクタリング

既存の処理にも定期的にリファクタリングを行い、安全かつ容易に仕様変更を行える状態を保つことを意識しています。CSSについても、途中からネスト記法を導入してセレクタの構造を整理し、保守性を高めています。またJavaScriptではモジュールに分割し機能ごとファイルを分け、依存関係の管理を容易に行えるようにしました。

## 今後の展望
- 現在は設定した内容がローカルストレージに保存されるため、端末・ブラウザ間の同期ができません。将来的にサーバー・データベースを導入し同期・共有を可能にしたいです。
